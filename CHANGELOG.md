## [Unreleased]

### Added

- iOS tiered drug index loading (`ios/drug-index-loader/PildoraDrugIndexLoader`, `data/`): the app now ships a compact **core** autocomplete index inside the bundle and downloads the **full** index from a CDN on first launch, so common medications and supplements can be added **fully offline on first run** with no network. A new `TieredDrugIndexProvider` serves autocomplete from the bundled core and **hot-swaps to the full index** once it's downloaded and verified, keeping latency `< 50 ms` against whichever tier is active. The background download shows **progress**, retries with backoff, and **falls back gracefully** to the core index when offline or on failure (autocomplete keeps working; the app retries later). Downloads are validated end-to-end — a signed-style **manifest** with schema/index versions plus SHA-256 + size checks on both the compressed and decompressed artifacts, gunzip on-device, and an open-and-validate step — so **updated drug data can ship without an app-store update**. All autocomplete queries remain **local-only** (no query text ever leaves the device); the only server-observable event is that a user fetched the public drug database, documented in the metadata-exposure model with the informational-only reference-data disclaimer. The `data/` ETL gains a `--tiered` mode emitting the core/full split (top-N common drugs + all supplements) with an `--index-version` stamp and a `manifest.json`. A dismissible in-app status banner and a Diagnostics row surface the active tier and download state (#68).

- iOS local notifications with dose actions (`ios/notification-scheduler/PildoraNotificationScheduler`): production local-notification scheduling that promotes the `notification-spike` (#23) strategy into a shippable, dependency-free feature slice. Schedules dose reminders as **local-only** notifications (no server push — a hard zero-knowledge constraint; the server never learns a user's dose schedule) with actionable **Taken / Snooze / Skip** responses, rotating them within the iOS **64-notification limit** via a remove-all-then-add `NotificationPlanner`. Ordering is **soonest-first with a priority tiebreak** — a deliberate refinement over the spike's priority-first sort that prevents near-term low-priority doses from being starved by far-future critical ones, so continuous replenishment (on launch, after each action, after CRUD) delivers every dose in the coverage horizon on time. Adds rich content (medication name, dosage, and user instructions verbatim — no dosing guidance), one-shot **snooze** re-reminders (+10/15/30 min) that survive rotation, **overdue** handling (badge count + summary notification), onboarding **permission** handling, and automatic **Apple Watch** mirroring (shared notification thread). The only type importing `UserNotifications` sits behind a `NotificationScheduling` protocol seam (`SystemNotificationCenter` for device, `InMemoryNotificationCenter` for tests), so the whole package — including a deterministic **48-hour / 24-medication stress simulation** asserting the queue never overflows and every in-window dose is delivered exactly once, in order — runs under `swift test` with no entitlements (CI `iOS Packages (macOS)` job). Notification `userInfo` carries only opaque identifiers, never health data; `DoseNotification` carries `vaultId` for multi-vault readiness. On-device delivery-accuracy testing remains gated on Apple Developer enrollment (#25). Documented in `docs/ios-notifications.md` (#49).
- iOS SwiftUI design system foundation (`ios/design-system/PildoraDesignSystem`): a shared, standalone package providing the visual foundation for all iOS/iPadOS/watchOS UI. Ships semantic **color tokens** (primary/secondary/surface/text/success/warning/error/info) with explicit light, dark, **and high-contrast** variants (resolved at render time via dynamic `UIColor`/`NSColor` providers, so Persona 2's large-text + high-contrast needs are met from day one), a Dynamic-Type **typography scale** that scales to accessibility sizes (xxxLarge+), a 4pt/8pt **spacing** + radius grid, and a base **component library** (`PildoraButton`, `Card`, `PildoraTextField`, `ListRow`, `StatusBadge`, `SourceTag`) where status is always conveyed by icon **and** text (never color alone), interactive elements meet the 44pt tap target, and VoiceOver labels/heading traits are built in. Includes a `DesignSystemCatalog` preview catalog (light/dark/Dynamic Type XL) and a contributor guide (`docs/ios-design-system.md`). `PildoraMedicationList` (dropping its interim local token subset) and `PildoraTodayView` are migrated onto the shared package, and the app target embeds it. watchOS shares the color tokens (Watch-specific components remain a separate concern) (#43).
- iOS medication CRUD with drug-name autocomplete (`ios/medication-list/`, `ios/drug-index/`, `ios/app/`): the medication feature now adds, edits, and deletes medications/supplements persisted in the encrypted vault database, wired into the runnable `app/` target end-to-end. A new read-only `PildoraDrugIndex` package provides `< 50 ms` on-device autocomplete over the ETL's FTS5 drug index (schema-identical `DrugIndexBuilder` seeds a dev index on first launch), with brand↔generic matching, supplement free-text entry, and queries that never leave the device (zero-knowledge). `PildoraMedicationList` drops its duplicate model types and now builds on the `PildoraDataLayer` records directly; mutations write through a `MedicationRepository` seam (database-backed with cascade deletes, plus an in-memory fake for previews/tests). The `app/` root hosts the medication UI on the encrypted database (vault bootstrap via the crypto FFI + `VaultDatabaseManager`, key stored in the Keychain) with the FFI smoke test preserved behind a Diagnostics tab, and real XCUITests cover add-via-autocomplete, supplement free-text, edit, and delete-with-confirmation. Adds a `v2` data-layer migration (`inventory.refillReminderEnabled`). Encryption at rest uses the `GRDBCIPHER` key-derivation path; SQLCipher linkage under SwiftPM is tracked as a follow-up, and the app currently runs on GRDB/plain-SQLite with the derivation path intact (no server is ever involved, so the zero-knowledge boundary is unaffected) (#48).
- iOS schedule engine (`ios/schedule-engine/PildoraScheduleEngine`): a pure-Swift, dependency-free computation layer that turns a medication's recurrence rule into concrete dose times. Supports daily, multi-daily (multiple times/day), every-N-days, specific days of week, cycling (e.g. 21-on/7-off, 5-on/2-off), and PRN (as-needed, no computed doses). Doses can be pinned to explicit `"HH:mm"` times or user-configurable morning/afternoon/evening/bedtime windows. `nextDoses(count:after:calendar:)` (for notification scheduling and the Today view) and `occurrences(in:calendar:)` compute times with wall-clock semantics — every query takes an explicit `Calendar`/`TimeZone`, so timezone travel and DST are handled by calendar arithmetic (spring-forward → next valid instant, fall-back → earlier occurrence). Includes `ScheduleRule.validate()` to reject impossible/overlapping schedules and a 46-case XCTest suite covering DST transitions and multi-timezone travel. Defines its own richer input model, independent of the persisted `Schedule` record; persistence wiring lands later. Documented in `docs/ios-schedule-engine.md` (#46).
- watchOS FFI validation (`ios/watchos-ffi-spike/`): confirms `pildora-crypto-ffi` compiles, links, and runs on watchOS. The XCFramework build (`ios/ffi-spike/build-xcframework.sh`) now emits stable watchOS slices (`watchos-arm64`, `watchos-arm64-simulator`) alongside iOS, and a SwiftPM XCTest bundle runs an encrypt/decrypt, wrap/unwrap, SQLCipher-key, and Argon2id suite on the watchOS simulator via `run-watchos-tests.sh`. Documents that Apple Watch Series 4–8 (`arm64_32-apple-watchos`, Tier 3) needs nightly + `-Zbuild-std` as an open deployment-floor decision, and that the 64 MiB Argon2id default must be profiled on-device (with a reduced-parameter fallback whose parameters must be persisted in vault metadata). Findings recorded in ADR-007 (#42).
- iOS encrypted data model layer (`ios/data-layer/PildoraDataLayer`): production SQLCipher-backed persistence graduating the storage spike into a package — five vault-scoped GRDB entities (`Vault`, `Medication`, `Schedule`, `DoseLog`, `InventoryRecord`), typed CRUD with cascade deletes, a versioned `DatabaseMigrator` framework, and a one-vault-one-file `VaultDatabaseManager` (each vault is its own encrypted file with iOS Data Protection). The SQLCipher passphrase is derived from the vault key by a new `pildora-crypto-ffi` function, `derive_sqlcipher_key` (HKDF-SHA256, domain label `pildora-sqlcipher-db-key`), so all cryptography stays in `pildora-crypto`; the package stays decoupled from the FFI via a `DatabaseKeyDeriving` seam and locks the derivation to the Rust output with a shared known-answer vector. Documented in `docs/ios-data-model.md` (#44).
- SRP-6a zero-knowledge authentication (`pildora-crypto::srp`): password-verified login where the server stores only a verifier and never sees the master password. Uses the RFC 5054 3072-bit group with SHA-256, derives the SRP secret from the existing key hierarchy's `AuthKey` (so the verifier inherits the full Argon2id work factor), and establishes a shared session key with mutual proof verification. Includes per-step known-answer test vectors and a client↔server handshake test. Documented in ADR-008 (#45).
- iOS Xcode Rust build phase (`ios/app/`): minimal XcodeGen-generated app that cross-compiles `pildora-crypto-ffi` for the active SDK/architecture via a Run Script build phase, so `Cmd+B` builds and runs the FFI bridge with no manual script step. Maps `$PLATFORM_NAME`/`$ARCHS`/`$CONFIGURATION` to Rust targets (device + simulator), `lipo`-combines multi-arch slices, and stages the static library for the linker; `generate-bindings.sh` regenerates the committed UniFFI Swift bindings on demand (#41).
- iOS secure memory wrapper (`ios/secure-memory/`): `SecureBytes`, a move-only (`~Copyable`) Swift type that securely zeroizes key material on `deinit` (via `memset_s`/`explicit_bzero`), with scoped `withUnsafeBytes`/`withUnsafeMutableBytes` accessors, a `secureZero` primitive, and documentation of which UniFFI calls return sensitive material. Resolves the Swift memory-zeroization hardening item from ADR-007 (#40).
- iOS Today view feature (`ios/today-view/`): chronological dose sections (morning/afternoon/evening/bedtime), dose states (upcoming/due now/overdue/taken/skipped/snoozed), one-tap confirmation with haptic feedback, swipe actions (taken/skip/snooze), PRN quick logging, and VoiceOver/Dynamic Type support.
- iOS medication list feature (`ios/medication-list/`): SwiftUI package with a searchable, category-grouped medication list, drug reference display (class, side effects, source + date attribution, informational-only disclaimer), manual inventory tracking with user-configurable low-stock thresholds and local refill reminders, a profile/settings screen, and on-device data export (decrypted JSON + Doctor Mode PDF). Self-contained against an in-memory sample store pending the data layer (#44), CRUD (#48), and design system (#43).
- CI: macOS job (`FFI (macOS)`) validating the `pildora-crypto-ffi` FFI pipeline — builds the crate for the macOS host, generates Swift bindings via `uniffi-bindgen`, cross-compiles for `aarch64-apple-ios` + `aarch64-apple-ios-sim`, and compiles the generated Swift to verify it is valid (#39)
- `pildora-crypto-ffi` crate: UniFFI bindings exposing `pildora-crypto` to Swift via FFI (ADR-007)

### Changed

- Roadmap updated to reflect ADR decisions: libsodium → `pildora-crypto` (RustCrypto), MIT open-core → AGPL-3.0, TypeScript/Hono → Rust+Axum, cbindgen → UniFFI (17 sections reconciled)
- Sync server language from Go to Rust + Axum across all documentation
- Crypto implementation decision: RustCrypto crates over libsodium bindings (updated ADR-001)
- `.gitignore` now commits `Cargo.lock` (workspace with binaries needs reproducible builds)
- Roadmap Section 8 rewritten to reflect consolidated tech stack
